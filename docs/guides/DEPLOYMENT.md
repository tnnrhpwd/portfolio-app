# Deployment Topology

The app is split across **two hosts** — Netlify (frontend + scheduled function) and
Render (backend web service). This doc is the single reference for how they fit
together, so the topology doesn't have to be reverse-engineered from
`netlify.toml` / `render.yaml`.

## The two halves

| Concern | Host | Config |
|---------|------|--------|
| Frontend (Vite/React SPA) | **Netlify** | `netlify.toml` |
| Backend (Express, port 5000) | **Render** | `render.yaml` |
| Scheduled keep-warm ping | **Netlify** | `netlify/functions/keep-warm.mjs` |

## Frontend — Netlify

- Build: `npm run build:netlify` → `npm install --prefix frontend && npm run build --prefix frontend`.
- Publish directory: `frontend/build`.
- It's a client-side SPA (Vite + React Router), so `index.html` serves all routes;
  a sitemap is generated by `frontend/scripts/generate-sitemap.js` at build time.
- `netlify.toml` carries SPA redirects, security headers (CSP/HSTS/etc.), and
  cache hints for hashed `/assets/*` and static pages.

### API base URL resolution

`frontend/src/config/api.js` is the single source of truth for the backend URL:

- **Dev**: relative `/api/data/` → Vite dev proxy → `localhost:5000`.
- **Production on `sthopwood.com`**: relative `/api/data/` → Netlify's `/api/*`
  proxy → Render (hides the Render origin from the browser).
- **Deploy previews / other domains**: direct to
  `https://mern-plan-web-service.onrender.com`.

## Backend — Render

- `render.yaml` blueprint: `rootDir: backend`, Node runtime.
  - Install: `npm install`
  - Build: `npm run build` (installs prod deps; no compile step)
  - Start: `npm run server` → `node server.js`
  - Health check: `GET /health`
- Free tier: Render **spins down after ~15 min of inactivity**.

## Keep-warm function

`netlify/functions/keep-warm.mjs` is a Netlify **scheduled function** (cron
`*/14 * * * *`, i.e. every 14 minutes) that pings the Render `/health` endpoint
to prevent cold starts on the free tier. It is infrastructure glue, not app code.

## Secrets

There are **no production secrets in the repo**. AWS Secrets Manager is the
single source of truth for every non-AWS secret (Stripe, JWT, DeepSeek, GitHub
token, …). At boot, `backend/utils/awsSecrets.js` (`loadAllSecrets`) hydrates
`process.env` from the `portfolio-app/production` secret. The only things
Render needs in its env vars are the AWS bootstrap credentials so it can reach
Secrets Manager. See [`SECRETS_MANAGEMENT.md`](SECRETS_MANAGEMENT.md).
